# Nadlantours — Railway + PostgreSQL

## تشغيل محلياً
1. ثبّت Node.js 18 أو أحدث.
2. نفّذ `npm install`.
3. اضبط متغيرات البيئة من `.env.example` (لا ترفع ملف `.env` إلى GitHub).
4. نفّذ `npm start` وافتح `http://localhost:3000`.

## النشر على Railway
1. ارفع محتويات هذا المجلد إلى GitHub.
2. في Railway أنشئ مشروعاً من مستودع GitHub.
3. أضيفي خدمة **PostgreSQL** إلى المشروع من زر **New**.
4. افتحي خدمة التطبيق → **Variables**، وأضيفي متغيراً اسمه `DATABASE_URL` واجعلي قيمته مرجعاً إلى متغير PostgreSQL: `${{Postgres.DATABASE_URL}}` (اختاري اسم خدمة قاعدة البيانات الفعلي إذا كان مختلفاً).
5. أضيفي `GEMINI_API_KEY` إذا أردتِ تشغيل المساعد الذكي.
6. أعيدي Deploy. ينشئ التطبيق جدول `bookings` تلقائياً عند أول اتصال ناجح.
7. افحصي `https://YOUR-DOMAIN/api/health`؛ يجب أن تظهر `database: connected`.

## التخزين والبيانات القديمة
- جميع الحجوزات الجديدة والتعديلات والحذف تُنفّذ على PostgreSQL.
- عند أول تشغيل للنسخة الجديدة، إذا كانت قاعدة البيانات فارغة وكان في المتصفح حجوزات قديمة، يحاول التطبيق نقلها مرة واحدة إلى PostgreSQL، ثم يمسح نسخة الحجوزات المحلية بعد نجاح الاتصال.
- ذاكرة التخزين المؤقت لبعض معلومات الوجهات قد تبقى في المتصفح؛ لا تحتوي على سجل الحجوزات.
- لا تضعي Volume على `/app`؛ قاعدة PostgreSQL المُدارة لا تحتاج Volume تضيفيه للتطبيق.

## تنبيه أمني مهم
واجهة الإدارة الحالية لا تحتوي على تسجيل دخول أو صلاحيات مستخدمين. لذلك لا تنشري بيانات زبائن حقيقية على رابط عام قبل إضافة تسجيل دخول وحماية لمسارات الإدارة وواجهات قراءة الحجوزات.
